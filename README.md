# Codex 额度托盘 0.2.34 开发候选


> 0.2.34 首次发布候选已完成云端编译、1,624 项测试及普通用户权限下的真实 Windows 更新生命周期隔离测试（6/6）。测试覆盖实际更新辅助程序，但不等于完整 WinForms 托盘的线上端到端自动更新验收；真实 GitHub / PowerShell 下载与完整应用联调仍需验证。发布状态以 GitHub Releases 为准，详见 [验证记录](docs/VERIFY-0.2.34.md)。

Windows 10 1903+ / Windows 11 x64 单 EXE 托盘工具。使用系统内置 .NET Framework 4.8；无需额外安装 .NET 8。

## 0.2.32 公共重置信息读取方式

按用户明确选择，本版公共重置信息只通过已安装的 PowerShell 7.5+ 获取：托盘调用固定脚本，PowerShell 匿名请求一次固定公共 API，并在 EXE 同目录生成 `reset-state.json`；托盘仅验证和读取这个 JSON。原直接 HTTP / WinHTTP 请求路径已移除，不会失败后换网络实现。额度、重置卡、TPS 和原有显示布局不变。

- 使用标准安装位置 `Program Files/PowerShell/7/pwsh.exe`，不搜索或启动别的 PowerShell、不额外安装运行时。
- 首次使用在 EXE 同目录生成版本化脚本；每次请求使用有界临时请求文件和唯一 requestId，完成后删除自己创建的请求文件。目录不可写、缺少 PowerShell、脚本受执行策略限制或任意失败，都静默隐藏附加行/红点，原有额度功能照常。不提权、不改 ACL、代理、环境或执行策略。
- PowerShell 不常驻，正常约 5 分钟启动一次，仍使用原抖动/退避、单请求和取消预算。12 秒包括主工具启动/等待/读回；同步系统调用返回与完整自有进程树清理可能更晚，未确认清理前不重叠启动。API 正文上限 64 KiB，JSON 信封上限 96 KiB；超限拒绝。失败不读取旧成功文件。
- 结果先写唯一临时文件，再原子创建/替换。文件写入或替换失败不会改用非原子覆盖或其它目录。相同 requestId、传输时间、HTTP/ETag 与严格 API schema 都校验通过才显示；历史 latest_reset 时间不当作过期缓存。
- 「查看连接诊断」显示 `PowerShell7Json`、固定错误阶段标签、HTTP/数字错误码与子进程退出码，不包含路径、原文或异常消息。打开诊断不触发请求。

原生 Windows 小验证工具的 EXE → PowerShell → 新 JSON 读回链路已由用户验证成功；这不等于正式托盘及已有文件替换已完成 Windows 验证。源码基于可核验的 0.2.30 归档恢复，详情见 [SOURCE-RECOVERY.md](docs/SOURCE-RECOVERY.md)。

## 数据来源

右键「数据来源」可选择自动模式或三个固定来源，并记住所选策略：

- 自动（默认）：依次尝试 CLI → VSCode 插件 → Desktop，直到真正返回可用额度；之后优先保持成功来源，不每次重新探测。

- Codex 桌面端：当前用户注册的官方 Desktop，以及与该安装严格匹配的既存官方用户级 runtime。
- Codex CLI：显式指定的 CLI，或 PATH/npm 中发现的 CLI。手动选中后只尝试此项。
- VSCode 插件：当前用户本地 VSCode/Insiders 的官方 OpenAI 扩展内组件。

手动模式只在所选来源中发现并选定一个组件；失败不切换其他来源。自动模式按明确顺序串行尝试，每个来源最多一次；只有上次成功来源的暂时性失败会等待 1 秒再重试一次，然后才尝试其他来源。全部失败后沿用 30/60/120/240/300 秒有界退避；服务端限流立即停止整轮，冷却 5 分钟，不用其他安装反复请求。若旧查询的清理超过 2 秒，会保留本程序持有的 Job、管道和文件租约，暂停新查询并持续退避确认退出；确认自有主进程、整个 Job 和管道完成后自动恢复。间隔逐步增至最多 30 秒，切换来源不会绕过保护，退出程序可停止等待。已成功读到的额度与原读取时间保留，显示“清理待确认，刷新暂停”，不把本地清理问题写成“服务未返回”。直接运行原安装位置，不尝试内嵌 reader，不复制或改名官方程序。选择 Desktop 不等于启动桌面 UI；使用其随包发布的 app-server 组件，可能受到安装权限或版本兼容限制。

成功来源不会把已保存的“自动”改写成手动选项。菜单勾选表示保存的策略；自动模式下，当前有效成功来源行另有 ●。发现候选不算成功，失败、过期、切换和清理异常都会清除成功圆点。0.2.17 的旧版来源设置首次升级会迁移为自动，之后可重新固定任一来源；保存失败明确提示。

切换策略时清空旧来源额度/重置卡、取消并回收旧请求，再立即查询新来源；过期结果及诊断不得覆盖新来源。模型/推理档位与计时信息保持原有独立本地读取逻辑，不随额度来源清空。

## 登录与安全边界

托盘只发送 initialize、initialized 与 account/rateLimits/read，不发送 login/logout、account/read、模型生成或重置卡消费请求，也不直接读取、导出或复制登录令牌。

所选官方组件可能按正常逻辑自行读取、续期并更新其已有登录；这包括组件启动时的内部行为，不能承诺严格“无续期/无写回”。这一边界已经单独说明并获用户同意。不同安装版本、认证存储或仅由宿主持有的登录可能不互通。

保持普通权限 asInvoker 和普通用户 Run 自启。不改变系统代理、防火墙、审计、执行策略或其他安全设置。旧内嵌模块源码仅作历史保留与回归测试，不打包到本版 EXE、也不用于运行时回退。

## 使用与定位

1. 退出旧版本，运行 CodexQuotaTray.exe。
2. 右键「数据来源」选择要验证的来源。切换后立即刷新，后续继续按既有间隔更新。
3. 失败时打开「查看连接诊断…」。诊断记录所选/保存策略、实际成功来源、本轮尝试顺序、发现候选数量、安全位置类别及排除原因、实际握手版本、发现/启动/握手/额度/退出阶段耗时、状态、数字错误或退出码。
4. 诊断有界、脱敏，不含完整路径、账号、令牌、代理地址、原始 stderr 或 JSON。未开始、未知、不可用分别标记，组件版本来自实际握手，不使用旧硬编码版本。

0.2.30 在同一「查看连接诊断…」窗口加入公共重置信息诊断：当前请求与最近完成请求分开记录，包含开始/完成时间、结果、HTTP 状态、阶段、耗时、固定错误类别及数字错误码、解析结果、数据是否存在、实际显示状态/隐藏原因和下次轮询时间。打开窗口只读取已有快照，不触发请求、不写入日志文件，也不记录服务原文、异常消息或地址。此版本仅增加定位信息，不改变请求、TLS、重试或显示规则；尚不能据此认定或修复用户机器未显示“上次重置”的原因。需要反馈时，复制窗口中的公共重置信息段即可。

诊断窗口一次捕获同一来源世代的不可变快照，分别展示当前轮和最近完成轮；来源尝试开始立即记录，异常也记录真实终态，不把上一轮失败和新一轮开始拼在一起。

用户已在 0.2.17 验证 CLI 与 VSCode 插件可用，Desktop 包内组件在 CreateProcess 阶段报访问拒绝 5。0.2.19 的用户实测在 Desktop 发现阶段报访问拒绝 5，尚未进入启动。0.2.20 移除发现过程额外打开所有祖先目录的权限要求，保留 Store 注册、无重解析路径及签名验证，并为失败增加具体 API 步骤诊断；尚未在用户 Windows 上验证，不能据此保证解决拒绝。未加入历史日志额度回退。

0.2.20 的后续 Desktop 实测已走过包资源验证，在第一个 runtime 的验证累计 12 秒时停止。0.2.21 将 Desktop 的 Framework 哈希明确选为 Windows CNG、使用 1 MiB 读取块，并将 12 秒预算限定为实际读取/哈希工作；签名与目录阶段不再挤占这项预算。512 MiB 单文件、2 GiB 阶段字节上限保留，共享客户端 40 秒协作截止，同步系统调用返回后才可检查停止。完整哈希、签名及启动前复验均保留，无缓存或复用信任结果。诊断明确资源限额类型、提供程序、字节量与耗时。云端慢流可复现旧预算行为。用户随后在同一台 Windows 的 0.2.21 手动 Desktop 模式验证成功：既存 runtime 与注册包字节/签名匹配，官方组件版本 0.162.0，正常返回额度并退出，未回退其他来源；整轮约 17.4 秒。这是一台机器的实测，不保证其他安装或版本，也不证明磁盘/CNG 单独性能。

右键菜单包含立即刷新、数据来源、主题、开机启动、自动更新、检查更新、连接诊断、关于/许可与退出；异常设置提示仅在需要时出现。额度、重置与历史速度信息集中在悬停卡。

Desktop runtime 只检查当前用户 `LocalAppData/OpenAI/Codex/bin/codex.exe` 或该目录下一层 16 位小写十六进制名称目录中的 `codex.exe`。候选必须关联当前已注册的官方 Store 包，与包内资源大小/SHA256一致，路径不经过重解析点，且本地缓存中的 Authenticode 信任及既知 OpenAI 发布者身份验证成功；启动前重新核验并保留只读文件租约。MSIX 合法硬链接不被当作重解析点拒绝。未验证的来源、证书、路径或更新期间变化会明确失败；不借此修改安全策略或制造一个可启动副本。实时 Desktop 父子进程关系未检查时诊断明确显示 NotChecked，包字节匹配不声称证明文件由谁创建。

实现参考 [LimitHalo 的既存 runtime 发现与身份约束](https://github.com/DenisShumilov/LimitHalo/blob/6e47f25a79578376dd22bbd5dd6038cdf35464c1/src/limit_halo/codex_discovery.py)。[codex-monitor-hud #7](https://github.com/LH-03/codex-monitor-hud/issues/7) 与 [codex-account-switcher-windows #1](https://github.com/Chisiki1/codex-account-switcher-windows/issues/1)有相关用户成功报告；这些不是官方稳定入口契约，也不替代本程序的 Windows 实测。

来源子菜单与顶层菜单使用同一托盘屏幕工作区：空间足够时正常展开，靠双屏接缝时向内展开；超大字体时限定尺寸，不借用旁边屏幕。真实 Windows 多 DPI/菜单行为仍需实测。

首次运行沿用普通用户自启默认；明确关闭后保持关闭。不会创建服务或计划任务。旧 --codex-path 仅影响 CLI 来源，不覆盖 Desktop/VSCode 的选择。

## 显示

悬停卡显示剩余额度、重置时间与重置卡到期时间。右上“更新于 HH:mm”是最近一次额度读取成功的本地时间，失败不会把它改成本次尝试时间；尚未成功时显示“尚未更新”。主题可选跟随系统、浅色、深色；高对比度优先。历史模型和档位来自本地相应轮次，找不到或冲突不猜测。

0.2.29 按接口实际返回的有效时长显示额度窗口，而不是按 Plus / Pro 名称决定。300 分钟和 10080 分钟分别显示为 5 小时和本周；只有一个窗口时保持单栏，同时返回时保持原双栏。不合成“未返回”的另一栏；实际 0% 与重置时间未知仍显示。异常或不完整额度对象保留上次可信快照并标过期，不误当作窗口消失。托盘数字仍沿用既有套餐优先策略，只在首选窗口确实缺失时回退实际可用窗口。

### 公共重置信息

0.2.29 仅在本机成功访问 [Codex Resets 公共 API](https://codex-resets.com/api/docs) 后，在原有账号重置日期与重置卡之间加入紧凑文字行：

- “上次重置”是公开公告或首次观察记录距今多久，不是当前账号的实际重置时间。
- “预计重置”优先显示尚待确认的明确预告，否则显示未过期的第三方 AI 预测。没有有效预告／预测就没有这一行，也没有红点。时间未给出时明确写“时间未定”；有预定时间时优先显示“约1小时内”等相对时间，按剩余分钟向上取整，宽度足够时同行附带本地具体时间（同日仅显示时分，跨日加月日）。宽度不足先省略具体时间，不缩小字号或换行；完整时间可在提示中查看。预定时刻已过显示“已到预定时间”，绝不推断已经重置。
- 标签文字链接 Codex Resets，悬停说明数据来源；右侧文字链接经校验的原始 Tibo 公告。原文地址缺失时保留文字但不可点击。也可从右键菜单使用键盘打开原文。
- 有效预告／预测在悬浮卡上标一个小红点；新的未读事件同时在托盘右上角标红点。单击托盘，或打开预计重置原文后，托盘红点清除；同一事件的重复轮询、概率或措辞变化不会反复提醒。悬浮卡红点仍表示当前有效预测。只保存最多 32 个已读事件摘要，不保存 API 内容或用户账号信息。

这是独立、可静默失效的附加信息。启动后由本机匿名请求固定 HTTPS 地址，不携带 Codex 登录、额度、日志或个人资料。超时、断网、限流、异常响应等都会隐藏全部新增行与红点，不保留空白位置，不弹出错误，不影响额度、重置卡与 TPS。正常约 5 分钟请求一次，带少量抖动；失败指数退避至约 1 小时，并遵守更长的 Retry-After。响应正文上限 64 KiB、超限拒绝，12 秒取消预算；ETag / 304 重验证避免盲用长缓存，不使用随机查询串。悬停、额度手动刷新和 TPS 轮询均不会请求此 API。

过期预测立即隐藏。明确预告超过预定时刻 24 小时仍未获执行确认，或无明确时刻的预告超过公告 7 天，会停止展示，避免永久悬挂。公共信息永远不更改账号额度、百分比、重置日期或重置卡；参考 [公开接口定义](https://codex-resets.com/api/openapi.json)。

0.2.27 优先在每条官方 token_usage_record 完成时更新响应有效速度估算，不再等整个工具回合结束。输出 token 已含推理，不重复相加；分母是有证据的日志请求到响应完成区间，包含首 token 等待及落盘延迟，不是纯生成 TPS。保持「GPT6.1 Sol 中  ≈ 30.2 tok/s」，缺新样本时整组保留最近历史值并标「上次 HH:mm」，不拼新型号旧数字。短回复不设 200 token 门槛，不用中位数遮住更新；修复有界发现/补扫、大正文、积压追赶与同时间排序。详情见 [OUTPUT-SPEED.md](docs/OUTPUT-SPEED.md)。

左侧 ⚡ 表示明确请求的 Fast 设置（ThreadRequestedSetting）。有数值的完整均速采用该样本完成时的会话设置快照，后续设置不改写历史样本；无数值元数据仍可显示同一会话最新设置。它不是服务器确认的实际服务档位，也不保证某个回合没有覆盖设置；未知或损坏记录不标，不能跨会话继承。诊断说明设置证据范围与 turnTierUnknown。

## 从源码构建

需要 .NET SDK 8（C# 12）或兼容更新版，构建依赖从官方 NuGet 恢复。接收者无需 SDK。当前发布不需要 Rust。

```sh
scripts/build-lightweight.sh
```

Windows 可用 scripts/build-lightweight.ps1。完整云端回归：

```sh
dotnet build CodexQuotaTray.sln -c Release -m:1
dotnet tests/CodexQuota.Tests/bin/Release/net8.0/CodexQuota.Tests.dll
dotnet build tests/CodexQuota.FrameworkSmoke -c Release -m:1
```

云端测试使用假协议和隔离样本，不读取真实登录、不访问真实账号、不请求模型。Windows Desktop/插件真实启动及公司策略仍由用户验证。检查记录见 [VERIFICATION.md](docs/VERIFICATION.md)，本次低占用排查与仍存在的 Desktop 校验开销见 [PERFORMANCE.md](docs/PERFORMANCE.md)。FrameworkSmoke 在云端仅编译，不能算 Windows 执行通过。

本工具非 OpenAI 官方产品；相关源代码出处及完整第三方许可保留于仓库 third_party、native/quota-reader 和 EXE「关于 / 许可」。

### 0.2.23 主题选择

右键「主题」可选跟随系统、浅色、深色；默认跟随系统。选择立即应用于菜单与悬浮卡，保存为独立的本地主题设置。保存失败会明确提示仅本次生效。固定浅/深色不会被系统主题变化覆盖；Windows 高对比度仍优先保证可读性。不会修改 Windows 系统主题。

### 0.2.25 启动时尝试显示托盘图标

程序启动后默认有限尝试一次，仅适用于 Windows 10；没有菜单开关或额外设置文件。使用隔离的同 EXE 子进程，匹配本程序完整路径、窗口和图标 ID，尊重明确隐藏的选择，不处理其他图标。未公开的 Shell 接口可能不可用，请求成功也不保证图标实际常驻。失败静默保持程序正常工作，不循环重试；可从托盘箭头中手动拖出。无需管理员，不修改系统全局选项。

## 自动更新（0.2.34 起）

程序默认自动检查 GitHub Releases、验证签名后下载更新，并在原路径替换和重启；右键菜单可关闭自动更新或手动检查。首次需要安装带更新器的版本。源码和更新包均从固定仓库 `breakingtime126/CodexQuotaTray` 发布。

更新下载优先使用已安装的 PowerShell 7，否则使用 Windows 自带的 PowerShell 5.1；原公共重置信息仍保持 PowerShell 7.5 要求。更新失败继续保留旧版，不提权；以管理员身份运行时不会自动安装更新。完整发布契约、安全边界与回滚说明见 [自动更新说明](docs/automatic-updates.md)。
