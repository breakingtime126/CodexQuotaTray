# 0.2.41 验证记录

## 变更范围

- 基于正式版 0.2.40 / fc57a4266fb54236e218b36bd252f3a873600efa。
- 按明确要求取消 Desktop 额度查询主动执行的 WinVerifyTrust、发布者证书提取和签名成功标志，不增加验签缓存。
- 当前诊断身份改为 RegisteredPackageMetadata，不再宣称文件已通过官方签名验证。旧诊断枚举仍可读取。
- 保留 Store 注册/来源/manifest 身份、x64 PE、尺寸/可用版本匹配、受限路径、防重解析点、只读租约、启动前复核、取消和 40 秒预算。
- TPS 全目录发现默认由 3 秒改为 15 秒；已跟踪文件仍每 3 秒增量刷新，未完成扫描及历史补读的追赶调度不变。
- 自动更新清单 RSA/SHA-256 签名、下载包 SHA-256 与大小校验以及正式发布的签名流程均不修改。
- FileVersion/AssemblyVersion 为 0.2.41.0，ProductVersion 为 0.2.41。沿用精确 release/0.2.41 分支发布门槛和 main 祖先检查，普通 main 推送不触发发布。

## 安全与行为边界

注册包身份、路径、尺寸和版本不是可执行文件内容真实性证明。同大小同版本的修改不再由额度查询路径检出；本工具不再确认目标文件由 OpenAI 签署。未修改 Windows 安全策略或系统签名强制机制。

新建或未追踪会话可能等待约 15 秒后才被发现，还需加上轮询对齐与遍历耗时，这不是硬性延迟上限。现有已追踪会话不受发现间隔延长影响。

## 已执行的验证

- Linux / .NET 8 核心回归 1787/1787 通过；net48 单 EXE 构建通过。计数较 TPS 单独候选少 3 项，原因是删除仅适用于旧签名路径的测试。
- 生产方法的合成 PE 测试覆盖 1 KiB、373,698,352 字节和 512 MiB 虚拟文件，其主体禁止读取，每次只显式读取 16 字节 PE 字段。
- 回归确认核心程序集不存在原签名验证类型或 wintrust.dll 导入；保留尺寸/版本/注册变化/路径/取消和租约相关检查。
- 更新清单错误签名、错误密钥、篡改载荷以及下载文件错误哈希/大小的拒绝测试仍通过。
- TPS 回归验证跳过全扫描时仍读取已跟踪文件的新增内容、新文件后续可发现、未完成扫描继续推进；指纹与文件身份检查不改。
- 合成 2,000 文件、等效 60 秒轮询中，全扫描从 20 次减少为 4 次，条目从 41,000 减为 8,200；Linux 读器 CPU 中位数 190 ms → 40 ms，逻辑内容读取量不变。详情见 [TPS 实验](PERFORMANCE-TPS-DISCOVERY.md)。
- GitHub Windows 正式构建与菜单/传输离线检查以本版 Actions 运行记录为准；版本发布后另行核对 Latest、签名 update.json、EXE 版本与下载哈希一致性。

## 不应夸大的结果

旧版 0.2.40 在用户 Windows 的独立线程实验中，一次 WinVerifyTrust 平均耗费约 2.271 秒线程 CPU、2.275 秒墙钟时间。此证实验证调用确实耗 CPU，但不是新版整进程 CPU 的实测降幅，也没有取得目标进程的 profiler 调用栈。

上述合成 TPS 数字不是 Windows 全程序降幅。新版尚未在用户电脑直接安装或启动，真实账号额度查询、托盘交互、普通用户更新生命周期和实际 CPU 改善仍需运行后观察。此发布通过既有自动更新通道交付，不手动替换用户电脑上的程序。
